# LLM rerank 文献：重排对象、输入输出与上游边界

日期：2026 年 10 月 13 日。本文暂不讨论具体业务或推荐毕业题目，先还原代表性论文的任务定义。

检索范围：以文本检索中的 LLM 文档/段落重排为主，覆盖基础比较方式、专用模型、效率、推理、上下文偏置及召回反馈。不是全部 LLM rerank 文献的穷尽目录，不包含推荐商品排序、机器翻译候选重排等其他任务。主要依据原始论文 HTML、正式出版页面和官方资料；不同版本与实验设置不能混用。下列示意输入输出均为解释性例子，不是论文逐字提示词。

## 1. 这些论文在重排什么

多数工作的对象是：**检索器针对一个查询，从语料库中找出的候选段落或文档。**模型要判断这些既有文本对查询的相关性，改进靠前位置的结果。

段落 passage 是较短检索单元；文档 document 可以是网页、论文摘要、完整文本等，具体随数据集而变。有些文章用 document 泛指检索单元，不能仅凭名称认定其处理了完整长文档。

通常不是排列 token，不是对 LLM 已生成答案打分，也不是要求生成新的证据。最终输出一般是原有候选的 ID 顺序；中间模型调用可能只输出一个分数、一个获胜 ID 或一组相关 ID。

```text
查询 q + 全量语料 C
        ↓ 第一阶段检索
候选列表 D_N = [d1, d2, …, dN]
        ↓ 重排模型/比较算法
新的候选顺序 π(D_N)，或其前 K 项
```

N 是候选池规模；单次模型实际看到的数量 b 可能是 1、2、几个或一个窗口；K 是排序关注的前部位置。三者不能混用。N=100 不等于每次都把 100 篇全文输入模型，也不等于这 100 篇均相关。

相关性金标 qrels 用于监督或评测，正常测试时不输入模型。初排分数有时用于融合或调度，但不是所有 LLM 重排提示词的必需输入。

## 2. 代表文献逐项对照

### 2.1 RankGPT：LLM 能否直接完成相关性排序

- 文献：[Is ChatGPT Good at Search? Investigating Large Language Models as Re-Ranking Agents，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.923/)；[公开全文](https://arxiv.org/html/2304.09542)。
- 重排对象：检索得到的候选文本段落。
- 单次输入：查询、排序指令、带编号的若干段落正文。
- 单次输出：编号排列，例如 `[3] > [1] > [2]`。长候选池通过滑动窗口聚合。
- 主要问题：生成式 LLM 能否通过提示完成段落排序，以及如何将排序能力蒸馏到较小模型。
- 上游处理：基准主要重排 BM25 Top100；窗口 20、步长 10。表中有特定基线及 GPT-4 成本控制设置的例外，不能把所有结果当作完全相同调用流程。
- 研究边界：验证给定候选时的重排能力，不证明 BM25 是最优召回器。

### 2.2 PRP：把困难的列表任务转成两篇文档的比较

- 文献：[Large Language Models are Effective Text Rankers with Pairwise Ranking Prompting，2023 预印本](https://arxiv.org/abs/2306.17563)；[全文](https://arxiv.org/html/2306.17563)。
- 重排对象：候选段落。
- 单次输入：查询、Passage A、Passage B。
- 单次输出：A 或 B 更相关，也可以比较两种答案的概率；由排序/聚合算法得到整个结果列表。
- 主要问题：直接打分或生成整张排序表对现成模型要求较高；成对比较能否提高零样本排序能力，并通过调度控制成本。
- 上游处理：其 BEIR 对比使用同一批 BM25 Top100；另外检查初始顺序变化。
- 研究边界：改变比较方式，没有补充候选池外文档。AllPairs 与排序算法变体的计算复杂度不同。

### 2.3 Setwise：一次比较多篇，减少排序调用

- 文献：[A Setwise Approach for Effective and Highly Efficient Zero-shot Ranking with Large Language Models，2023 预印本 / SIGIR 2024](https://arxiv.org/abs/2310.09497)；[全文](https://arxiv.org/html/2310.09497)。
- 重排对象：候选段落/文档。
- 单次输入：查询与一个小候选组。
- 单次输出：组内最相关文档的标识；也讨论使用标识概率的实现。
- 主要问题：两两比较调用较多，整列表生成成本较高；让一次比较提供更多信息，提升效果—效率折中。
- 上游处理：主实验使用 BM25 Top100，主要关注 Top10；比较初排、逆序与随机序。
- 研究边界：从已有池中找前部结果，不负责查找池外文档。这里的“选一个最佳”不等于 TS-SetRank 的“选出所有相关项”。

### 2.4 RankZephyr：开源列表排序的效果与鲁棒性

- 文献：[RankZephyr: Effective and Robust Zero-Shot Listwise Reranking is a Breeze!，2023 预印本](https://arxiv.org/abs/2312.02724)；[全文](https://arxiv.org/html/2312.02724)。
- 重排对象：候选段落列表。
- 单次输入：查询、带编号的候选文本窗口。
- 单次输出：窗口内的编号排列，再通过滑窗得到列表排序。
- 主要问题：缩小开源模型与闭源排序模型的能力差距，改善初始顺序及候选数量变化下的表现。
- 上游处理：明确分析 BM25、SPLADE++、RepLLaMA、ADA2 四种初排器，以及 Top20/Top100 候选条件。
- 研究边界：它实际考虑了上游质量，只是没有把优化这四个检索器作为主要方法。标题中的 zero-shot 不意味着模型从未训练；它使用教师排序进行蒸馏。

### 2.5 RankLLaMA：用 LLaMA 构建专用的相关性打分器

- 文献：[Fine-Tuning LLaMA for Multi-Stage Text Retrieval，2023 预印本](https://arxiv.org/abs/2310.08319)；[全文](https://arxiv.org/html/2310.08319)。
- 重排对象：分别研究短段落和完整文档任务。
- 单次输入：查询与一篇候选文本。
- 单次输出：一个相关性分数，各候选按分数排序；不要求生成 ID 序列。
- 主要问题：如何将 LLaMA 微调为有效的检索与重排模型，并利用更长输入处理文档。
- 上游处理：同一论文研究 RepLLaMA 检索器与 RankLLaMA 重排器。段落设置重排 RepLLaMA Top200；文档设置重排 Top100。
- 研究边界：这是同时改进两阶段模型的反例，不能说重排论文都忽视上游。文档输入仍有长度上限，不代表任意长全文无损输入。

### 2.6 FIRST：减少排序序列解码，并对齐排序训练目标

- 文献：[FIRST: Faster Improved Listwise Reranking with Single Token Decoding，EMNLP 2024](https://aclanthology.org/2024.emnlp-main.491/)。
- 重排对象：候选段落列表。
- 单次输入：查询及带标识符的多个候选文本。
- 模型输出/算法读取：首个生成位置的候选标识符 logits，由这些值构造顺序，不需要自回归生成完整排列。
- 主要问题：完整 ID 序列解码慢；一般语言建模损失不能充分体现重要排序错误的代价。
- 上游关系：主方法优化重排；论文也用排序输出提供相关性反馈来改善检索器。
- 研究边界：节省输出解码不等于消除输入计算，也不是让 LLM 直接读取全量语料。

### 2.7 Qwen3-Reranker：面向多语言、任务指令的逐篇相关性判断

- 文献：[Qwen3 Embedding: Advancing Text Embedding and Reranking Through Foundation Models，2025 技术报告](https://arxiv.org/html/2506.05176)。
- 重排对象：检索候选文本，评测覆盖多语言、代码、长文档及指令相关任务。
- 单次输入：任务指令 I、查询 q、一篇候选 d。
- 单次输出/算法读取：yes/no token 的 logits，经归一化形成相关性分数，再排序。
- 主要问题：利用基础模型与训练方法提高跨语言、跨任务的相关性建模能力。
- 上游处理：重排对照使用 Qwen3-Embedding-0.6B 召回的同一 Top100；该报告本身同时研究 embedding 和 reranker。
- 研究边界：输出 0～1 分数不自动保证它在任意新领域都是校准后的真实概率。

### 2.8 Rank-R1：复杂相关性判断需要推理

- 文献：[Rank-R1: Enhancing Reasoning in LLM-based Document Rerankers via Reinforcement Learning，2025 预印本](https://arxiv.org/abs/2503.06034)；[本文核验版本全文](https://arxiv.org/html/2503.06034)。
- 重排对象：查询对应的候选文档，重点检查复杂查询。
- 单次输入：查询、一组候选、推理与选择指令。
- 单次输出：推理过程及组内最相关候选标签；堆排序组织多次调用，最终输出列表。
- 主要问题：直接选择候选未充分利用推理能力；通过 GRPO 和相关性标签训练推理型重排，无需人工推理过程标签。
- 上游处理：实验主要使用 BM25 Top100；论文明确标注某些引用的 RankGPT 成绩来自不同 BM25 实现。
- 研究边界：不同上游的外部结果不能完全用于隔离模型增量；生成理由也不是最终用户答案。

### 2.9 TS-SetRank：批次上下文使相关性判断波动

- 文献：[Contextual Relevance and Adaptive Sampling for LLM-Based Document Reranking，ACL 2026](https://aclanthology.org/2026.acl-long.94/)；[2025 预印本方法与实验全文](https://arxiv.org/html/2511.01208)。
- 重排对象：已有候选文档池。
- 单次输入：查询与抽样得到的一批候选。
- 单次输出：推理及判为相关的文档集合，可对应逐文档二元反馈；累计后验估计得到最终排序。
- 主要问题：候选组成和位置影响判断，如何在有限预算中采样和聚合，而非依赖一次比较。
- 上游处理：上述预印本使用 BM25 Top100；BRIGHT 使用基准提供的 GPT-4o 改写查询改善第一阶段结果。
- 研究边界：确实采用上游改善措施；但只在现有候选池内采样。正式复现需核对会议版的配置差异。

### 2.10 CapCal：去除输入位置带来的排序偏置

- 文献：[Learning from Emptiness: De-biasing Listwise Rerankers with Content-Agnostic Probability Calibration，ACL 2026](https://aclanthology.org/2026.acl-short.68/)。
- 重排对象：列表式重排的候选文档。
- 输入：正常查询与候选列表，另用内容无关占位输入估计偏置。
- 输出：校准后的候选 logits 与相应排序。
- 主要问题：模型对输入位置具有与内容相关性无关的先验；通过免训练校准减轻这种偏置。
- 上游关系：处理候选进入模型后的偏置，不补回缺失文档。此条核验至正式摘要，未逐项核查其全部实验初排器。

### 2.11 SlideGar：直接处理上游漏召回

- 文献：[Guiding Retrieval using LLM-based Listwise Rankers，2025](https://arxiv.org/abs/2501.09186)；[全文](https://arxiv.org/html/2501.09186)。
- 重排对象：初始候选及通过反馈新增的文档。
- 算法输入：查询、初始排序、语料文档相似图、窗口与计算预算；内部 LLM 仍接收查询和候选窗口。
- 输出：可能包含初始候选池之外文档的最终排序。
- 主要问题：传统重排无法找回没被召回的结果，即 bounded recall；将列表重排反馈用于图上扩展候选。
- 上游关系：明确改动召回—重排流程，不能归为纯粹固定候选重排。

## 3. 为什么可以单独研究重排

### 3.1 第一性原理没有规定必须先把上游优化到极限

下面是基于多阶段检索设计作出的分析，不是某篇论文的原句。

系统目标是以有限延迟和计算成本，从巨大语料中找到靠前的高相关结果。可以分别考察：

1. 候选覆盖：相关文档是否进入 D_N？
2. 候选排序：进入 D_N 后，它是否被放到适当位置？

第一阶段通常利用可索引的词项或向量表示高效筛选；第二阶段对少量候选进行更细的查询—文档联合计算或候选间比较。让第一阶段承担全部细粒度判断，可能失去其检索效率；让 LLM 扫描全库，成本也可能不可接受。[SlideGar 背景论述](https://arxiv.org/html/2501.09186)

因此优化对象是质量—成本折中。改进召回和改进排序可以并行，也可以协同；不能仅凭流水线先后顺序决定哪一类研究合法。

### 3.2 固定输入，是隔离变量，不是宣称输入完美

相同查询、相同候选文本与同一评测协议下，比较两个重排器，可以判断候选内排序能力是否改善。若同时换召回器和排序器，仅看总分就难以分辨增益来源。

但这个结论是有条件的：它不自动推广到任意召回器、候选规模或数据域。RankZephyr 更换多种上游，正是在扩大这种结论的适用边界。

### 3.3 候选池不全相关，是排序的正常输入

相关性筛选本来就是任务的一部分。要求上游先把所有无关文档去掉，可能相当于要求上游提前解决昂贵的相关性判断。

例如，100 篇候选中只有 1 篇相关，但它处在第 80 名；把它排到第 1 名仍是明确的排序改进。输出 Top20 的评测截断，不表示作者承诺 20 篇全相关。若需要返回 0/1/多条或拒绝结果，则应另外定义截断/相关性判定任务。

### 3.4 重排承认召回上限

对纯候选内重排，若 K≤N，相关文档集合为 R，则：

`Recall@K(重排结果) ≤ |D_N ∩ R| / |R| = Recall@N(候选池)`

这是按已知完整相关集合定义的关系；实际数据 qrels 不完整时，只能评估标注覆盖下的召回。重排可以提高小 K 的召回及前部排序，但不能增加整个固定候选池已覆盖的相关文档数。

若候选池完全没有相关文档，纯重排无法恢复它们；这时需要改善召回、扩展候选或识别无结果。SlideGar 正是针对第一种限制扩展研究范围。

## 4. 如何判断论文是否充分考虑了上游

| 文献做法 | 能支持什么 | 不能支持什么 |
|---|---|---|
| 固定同一候选池比较重排器 | 给定输入时的排序增量 | 上游最优、任何输入都有效 |
| 更换召回器、N 和顺序 | 对这些已测试条件的稳健性 | 未测试条件的全面保证 |
| 同时训练 retriever 与 reranker | 整体流程的改进 | 若缺少拆分对照，不能将全部提升归于重排 |
| 用重排反馈补召回 | 可改善候选覆盖与最终排序 | 不再是纯候选内排序能力比较 |

进一步可做的诊断是候选池内 oracle 排序：按已有金标将该池排到最好，比较实际排序与该上限的差距。这能帮助区分覆盖不足与排序不足；它是建议的分析手段，不能声称上述论文全都做过。

已有论文采用 BM25，也不代表其上游选择一定足够有说服力；预算、历史可比性、较强召回器下是否仍有增益，均可继续审查。论文被发表并不等于解决了所有系统边界问题。

## 5. 阅读顺序

先读 RankGPT 了解任务，再读 PRP 与 Setwise 理解比较方式；读 RankLLaMA、Qwen3 理解逐篇打分；读 RankZephyr 看上游质量与输入变化；随后按兴趣读 FIRST、Rank-R1、TS-SetRank、CapCal；最后读 SlideGar 理解什么时候必须突破固定候选池。

最需要记住的区别：**模型单次输出不一定是完整排序；候选规模不等于单次输入规模；重排改进不等于召回覆盖改进；候选里存在无关文档不等于输入无效。**
