# 商品文本重排：文献与开题候选问题

当前确认场景：query + [(item ID, 商品标题/描述/属性文本)] → item 相关性排序。不是基于历史交互预测下一次购买；不预设单篇文本必须很长。描述、证据摘录、生成理由是不同输入，需分别定义。

检索日期：2026-10-15。以下为针对问题定义、方法和局限的阅读，不是全部论文完整复现或穷尽检索。尚未确定题目。

## 代表工作

| 文献 | 解决的问题 | 做法与任务边界 |
|---|---|---|
| [Rec-R1](https://arxiv.org/html/2503.24289)，§3.3、附录E.3 | 通用生成模型与商品排序目标不充分对齐 | 用排序质量反馈优化 LLM；输入 query、item ID、元数据，输出 ID 排列；ESCI 派生固定候选实验，存在排除零召回查询的筛选条件 |
| [LREF](https://arxiv.org/html/2503.09223)，2025 | 商品相关性判断偏乐观，部分匹配被判成较强匹配 | 数据选择、专家解释/规则遵循/决策反思三类推理监督、DPO；主要是 query-product 相关性分类，不是一次生成完整列表 |
| [Rationale-Guided Distillation](https://aclanthology.org/2025.coling-industry.12/)，COLING Industry 2025 | LLM 相关性判断成本高 | 训练时用理由生成辅助任务蒸馏到 cross-encoder，部署仅保留评分器；理由是训练监督，不是每次推理输入的既有解释 |
| [Hint-Augmented Re-ranking](https://aclanthology.org/2025.ijcnlp-short.19/)，2025 | “最好、最适合”等最高级查询的隐含标准难匹配 | LLM 将查询拆成属性提示，辅助小模型排序；[代码和数据](https://github.com/yilunzhu/superhints/)；包含合成查询及模型生成标注，需审查标注与评测独立性 |
| [REAlign](https://arxiv.org/html/2608.02500)，2026预印本 | 多要求查询中，主题相关却违反关键条件的商品被抬高 | 需求—证据对齐，区分满足/违反/无证据；构造定向难例，以 R-GRPO 优化部分列表；已经覆盖缺证据与不满足的区分 |
| [Beyond Relevance](https://arxiv.org/html/2609.23646)，2026预印本 | 粗粒度相关性监督缺乏细致语义信息 | 结构化属性、解释、人工复核；最终为轻量检索器+MLP重排。其75条测试查询上，合成注释未超过不使用该注释的已训练基线；不能外推为所有LLM理由必然有害 |
| [LLMs Struggle to Rank Products Robustly](https://openreview.net/pdf?id=dVqdhHjpKm)，2026公开稿 | 商品规格不变，叙述表达仍改变排序 | FramingBench 测试产品比较文章中的表达影响；[公开数据卡](https://huggingface.co/datasets/framingbench/framingbench)。本轮PDF直读受站点验证阻碍，只核对到搜索索引中的原文摘要及数据卡；不能声称已经读透其所有缓解实验 |

## 数据

- [Amazon ESCI](https://github.com/amazon-science/esci-data)：query、商品ID、标题、描述、属性要点、E/S/C/I标注。可作主排序数据，原始标签不包含每条属性的证据状态或独立理由质量。
- [WANDS](https://github.com/wayfair/WANDS)：480查询、42,994商品、233,448相关性判断；含描述与属性，可作跨数据集验证。
- FramingBench：辅助表达干扰诊断；原场景为比较文章，拆成独立 item chunk 会改变任务，需明确报告。
- SuperHints：研究最高级查询的候选；不等同于原始ESCI。
- REAlign 的 Shop-Need/KS-Need：论文报告构建的固定候选评测；本轮未验证仓库实际数据可下载性，不承诺开箱即用。

## 开题候选：只选一个

### A. 事实不变的描述表达导致错误排序偏移（优先阅读）

问题句：在固定候选商品重排中，保持与查询相关的商品事实不变，描述的评价性措辞或叙事方式仍导致 LLM 的 item 排序偏移。

直接证据：FramingBench 报告该现象。潜在贡献是更有效的缓解，而不是重新发现表达偏置。已有去修辞/中性改写路线必须进一步核对；不能直接声称“先抽事实再排序”原创。

拟题：《面向商品文本重排的描述表达偏置缓解方法研究》。方法探索可围绕事实保持的表示学习或一致性约束，但不能只机械套用现有顺序一致性损失。评价需同时检查排序相关性与稳定性；忽略全部内容也可能稳定，却无用。真正改变商品事实的输入应允许改变排序。

### B. 生成理由引入错误判断（有明确前置条件）

问题句：在附加自动生成匹配理由的商品重排中，理由包含原始描述不支持的断言时，模型错误抬高候选。

Beyond Relevance 支持“合成注释不总有收益”，但不是此因果机制在列表式LLM中的完整证明。需要保留原始描述作为核验依据；若输入只有理由，则无法区分理由忠实性。创新必须超过不用理由、简单核验、查询级路由及常规事实一致性方法。仅当实际采用生成理由时才适用，不为选题人为添加多余模块。

### C. 属性的归属范围混淆（机制候选）

问题句：商品描述提及配件、兼容设备或其他型号时，模型把这些对象的属性误归给当前 item，造成相关性高估。

示意：标题包含“适用于支持无线充电的手机”，并不能推出正在出售的手机壳支持无线充电。该例只说明归属歧义，不直接给真实商品判标签。

LREF、REAlign 是直接近邻，但本轮尚未找到足够证据证明“归属混淆”是它们未解决的系统性残余错误。优先级低于A，不能当前直接宣布创新成立。

## 不能作为新贡献的宽泛想法

泛泛提出LLM排序、逐项属性核验、区分未知与不满足、生成理由蒸馏、查询分解、使用NDCG强化学习，均已有直接工作。场景可以成立，研究问题和方法原创性仍须分别论证。
