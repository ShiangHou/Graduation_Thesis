# 毕业论文选题第二版修订版

修订日期：2026-10-15。

版本性质：开题阶段的讨论归档，尚非最终开题报告。已确认任务场景；研究问题、题目及算法仍待文献复核与讨论。本轮未开展复现实验。

## 一、导师反馈与修改原则

第一版存在两项主要问题：

1. 将“出现什么现象、为什么出现、如何解决”并列展开，范围过宽，没有唯一核心问题。
2. 过度依赖业务中的候选质量假设。精确查询与模糊查询的相关结果数量不同，不能默认 Top-K 都相关；重排不能替代上游召回。

本轮按如下形式寻找技术问题：

> 在明确任务中，某类方法遇到某个具体条件，会产生可观察的错误；已有方法对该错误还有什么不足？

现象、机制和方法可以构成研究过程，但不再写成三个并列的大目标。先确定问题，不预先堆叠一致性训练、强化学习等算法模块。

## 二、讨论过程与方向变化

| 阶段 | 内容 | 当前定位 |
|---|---|---|
| 第一版 | 金融搜索、长候选列表、稳健性及预算优化 | 历史方案 |
| 通用重排调研 | pointwise、pairwise、listwise及上游边界 | 基础知识 |
| 小问题初筛 | 输入顺序、证据位置、排除约束、发布日期偏置 | 备选阅读记录 |
| 长文档重排 | 长正文中的证据选择、位置与压缩 | 已调研，不作为当前必要前提 |
| 本轮确认 | query + item及附带文本 → item相关性排序，以商品搜索为载体 | 当前任务场景 |

单篇文档长、候选列表长、商品描述长度是不同因素。本版不为延续历史题目而强制保留“长序列”。

## 三、已确认的任务定义

给定查询 q 和候选集合 C = {(id_i, t_i)}，id_i 标识商品，t_i 包含该商品的标题、描述或属性。模型根据文本判断商品满足查询需求的程度，输出候选商品 ID 排序。

```text
Query：适合跑步、支持防水的无线耳机
Item A：商品ID / 名称；文本：支持IPX7防水，带运动耳挂……
Item B：商品ID / 名称；文本：主打室内降噪，不支持防水……
输出：[A, B]
```

这是自拟结构示例，不是数据集原始样本或实验结果。当前不规定每个chunk必须500字，也未决定采用逐项评分还是一次生成列表。

附带文本需区分：

- **客观描述**：商品属性和功能，最容易直接使用公开数据。
- **查询相关证据**：从商品资料抽取的片段，需要明确抽取流程。
- **生成理由**：模型解释商品为何适合查询，需要额外生成且未必忠实。

已确认的是item配文本的结构，不等于已决定加入生成理由。单独输入商品名称也不等于基于描述证据的排序。

这属于查询驱动的搜索相关性任务，不是根据历史交互预测下一次购买。固定候选可以隔离重排方法，但不能消除召回上限。不要求每条查询有多个相关商品，不承诺恢复未召回商品。仅分析有效商品已召回的查询时，须披露条件化筛选。

## 四、代表文献与已有解决办法

| 文献 | 问题 | 方法与边界 |
|---|---|---|
| [Rec-R1](https://arxiv.org/html/2503.24289)，§3.3及附录E.3 | 通用生成行为与商品排序目标未充分对齐 | 用排序质量反馈优化LLM，输入query与item元数据、输出ID列表；ESCI派生实验筛除了部分零召回查询 |
| [LREF](https://arxiv.org/html/2503.09223)，2025 | 部分匹配被乐观地高估为较强匹配 | 数据筛选、多种推理监督、DPO；主要是逐对相关性分类 |
| [Rationale-Guided Distillation](https://aclanthology.org/2025.coling-industry.12/)，2025 | LLM相关性判断成本高 | 理由生成辅助训练小型cross-encoder，部署仅保留评分器；理由是训练监督 |
| [Hint-Augmented Re-ranking](https://aclanthology.org/2025.ijcnlp-short.19/)，2025 | “最好、最适合”等查询隐含比较标准 | 拆成属性提示辅助轻量排序；数据含合成查询与模型生成标注 |
| [REAlign](https://arxiv.org/html/2608.02500)，2026预印本 | 主题相关但违反关键要求的商品被抬高 | 要求与证据对齐，区分满足/违反/无证据，以需求感知奖励训练；上述区分已不是空白 |
| [Beyond Relevance](https://arxiv.org/html/2609.23646)，2026预印本 | 粗粒度监督缺乏细致语义信息 | 结构化属性与解释、人工复核、轻量重排；小规模测试中合成注释总体未超过相应无注释基线 |
| [LLMs Struggle to Rank Products Robustly](https://openreview.net/pdf?id=dVqdhHjpKm)，2026公开稿 | 商品规格不变，叙述方式仍影响排序 | FramingBench诊断表达干扰；原场景为商品比较文章 |

本轮阅读深度不一，不宣称逐页读完所有论文。最后一篇PDF直读受站点验证阻碍，只核对到原文摘要索引和数据卡，其完整缓解实验仍待阅读。

因此，LLM排序、逐项属性核验、理由蒸馏、查询分解、NDCG强化学习均有直接近邻，不能仅换模型或重新组合模块就主张创新。

## 五、候选小问题

### A. 描述表达偏置——第一阅读优先级，尚未定题

问题句：在固定候选商品的LLM重排中，保持查询需求和相关商品事实不变，仅改变评价性措辞或叙事表达，仍产生不合理的排名偏移。

暂定题目：**《面向商品文本重排的描述表达偏置缓解方法研究》**。

FramingBench提供现象依据，但再次发现现象不是创新。需要核对现有中性改写、事实抽取等缓解方法，再找它们的具体不足。事实保持的表示学习或约束只是方法探索，尚未证明原创或有效。

评价须同时检查相关性与稳定性：完全忽略输入也可能稳定；原始排序不自动是真值；真正改变商品事实时应允许排序变化。改写还需核验未增删关键事实。

### B. 无证据生成理由导致误排序——条件性备选

问题句：商品附带自动生成理由时，理由包含原始描述不支持的断言，模型却采信并抬高候选。

仅在实际采用理由输入时成立，不为选题人为添加模块。需保留原始描述作核验。Beyond Relevance支持“合成信息不总有收益”，但不是该因果机制在列表式LLM中的完整证明。应超过不用理由、简单核验及已有路由方法。

### C. 属性归属混淆——直接证据待补

问题句：描述同时涉及配件、兼容设备或其他型号时，LLM将关联对象的属性误归给当前item，造成相关性高估。

粒度较小，但尚未确认这是LREF、REAlign等方法未解决的系统性残余错误，当前不能认定创新成立。

| [Amazon ESCI](https://github.com/amazon-science/esci-data) | query、商品ID、标题、描述、属性要点、E/S/C/I标签 | 主排序评价候选 |
| [WANDS](https://github.com/wayfair/WANDS) | 480查询、42,994商品、233,448相关性判断，含描述和属性 | 跨数据集验证候选 |
| [FramingBench](https://huggingface.co/datasets/framingbench/framingbench) | 商品比较文本的表达干扰 | A的诊断参考；拆成独立item chunk须说明改造 |

公开相关性标注不等于逐项属性证据或理由忠实性标签，专项问题可能需要补充人工核验。改变query或商品事实后，不能不经审查沿用旧相关性标签。

## 七、下一轮工作与确认边界

1. 优先读透FramingBench的变换约束、评价指标、缓解方法及其局限。
2. 对照Rec-R1，明确列表生成或逐项评分的研究设定。
3. 核对ESCI/WANDS实际字段完整性、文本长度、标注规则与适用子集。
4. 找到已有方法的一项具体不足后，再确定最终问题句、题目和方法。

**已确认：任务场景、从具体技术错误出发的选题原则。未确认：最终题目、创新点、算法、算力及训练规模。A只是阅读优先级，没有实验结果。**
