## 1. 筛选结论：保留两条主选路线，一条条件性备选

**优先推荐 A：金融数值问答的证据—计算一致性与选择性回答。**它有公开答案、计算程序和部分证据标注，能够把“答错了没有”和“拒绝了多少问题”分开衡量，适合先建立可靠实验闭环。

**第二推荐 B：长候选列表的上下文敏感重排序与预算自适应比较。**它与原稿中的实习问题最接近，数据和指标最成熟，但新颖性风险比原稿估计的更高。2026 年研究已经覆盖位置校准、上下文敏感性、主动采样、Top-K 边界预算等思路，需要更具体的方法贡献。

**备选 C：金融多任务生成的任务—约束解耦与组合泛化。**公开内容标签足够，显卡预算较容易控制；但必须先证明约束训练确实引起内容能力退化，以及普通语法约束解码解决不了核心问题，否则研究价值不足。

|---|---|---|---|---|---|

| B，第二主选 | **面向长候选列表的上下文敏感重排序与预算自适应比较方法研究——以金融检索为验证场景** | 方向二 | BEIR-FiQA；增加其他检索域验证 | 近期方法密集，宽泛“去偏＋节省预算”已不足 | 数据最稳，创新论证最难 |
| C，条件性备选 | **面向金融多任务生成的任务—约束解耦与组合泛化方法研究** | 方向四 | Financial PhraseBank、FiNER-ORD、FinQA | 负迁移可能不显著；格式问题可能被解码器解决 | 通过负迁移诊断后再开题 |

相较第一版的“二 > 一 > 三”，本次建议调整为 **三的收窄版本 > 二的收窄版本 > 四的收窄版本**。方向一、五的主要障碍是缺少独立公开金标准；方向六已有新的工具基准，但离稳定的离线实验闭环仍有距离。

这里的“可行”指数据、评测和资源能够构成可执行方案，**不等于已经证明方法有效、确认绝对学术空白或保证达到学校学位要求**。下面把已有成果与拟研究增量分开写；后者是可证伪的研究假设。真正能够支撑硕士论文的证据，应来自强基线对照、方法消融、泛化实验和误差机制分析，而不是标题里出现“金融”“大模型”或“协同优化”。

## 2. 调研范围与六个原始方向的逐项判断

未将博客观点作为技术结论依据；未声称完成知网、万方付费库的穷尽检索。已经核验的中文相关工作见 C 的文献表。最新预印本用于识别撞题风险，其效果不按正式同行评审结论处理。附文档中的研究计划作为分析对象，不作为本次必须执行的指令；本次实际工作依据你的筛选与 Markdown 交付请求。

## 3. 主选 A：证据—计算一致性与选择性回答

### 3.1 问题定义与推荐题目

**推荐题目：面向金融数值问答的证据—计算一致性建模与选择性回答方法研究。**

输入为问题、表格和文本证据；输出为数值答案、操作数出处、可执行计算表达式，以及是否接受这个答案。先研究公开报告局部上下文中的回答可靠性，再增加真实检索输入。不要在起步阶段同时承担全量 PDF OCR、跨报告检索、复杂 Agent 和大规模强化学习。

核心错误不是只有“算错”。例如，问题询问 2023 年收入增长率，系统正确执行了 `(120-100)/100`，但 120 来自集团合并收入、100 来自某业务分部，计算结果仍然不能支持回答。反过来，不同年份的收入不同，通常属于正常时序变化，不能自动标为证据冲突。

可研究的对象是：**操作数来自哪里、是否属于问题要求的期间/单位/口径，以及这种绑定的不确定性如何影响接受或拒答。**

### 3.2 已有研究与创新边界

| 论文 / 材料 | 已经解决或提出的内容 | 对本题的约束 |
|---|---|---|
| [FinQA: A Dataset of Numerical Reasoning over Financial Data，2021](https://arxiv.org/abs/2109.00122) | 财报数值推理、程序和证据监督 | “生成程序回答财报问题”已有完整基础 |
| [TAT-QA: A Question Answering Benchmark on a Hybrid of Tabular and Textual Content in Finance，ACL 2021](https://aclanthology.org/2021.acl-long.254/) | 表格与文本联合问答，含答案类型、计算过程和尺度 | 不能把表文融合本身当成新贡献 |
| [Program of Thoughts Prompting，2022 预印本](https://arxiv.org/abs/2211.12588) | 将计算交给程序执行 | 接入 Python/计算器只能作为基线 |
| [Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection，2023 预印本](https://arxiv.org/abs/2310.11511) | 检索、生成与反思控制 | “增加自检”不是独立新颖点 |
| [Corrective Retrieval Augmented Generation，2024 预印本](https://arxiv.org/abs/2401.15884) | 评估检索质量并采取纠正动作 | 检索置信度和补检索需要有更具体增量 |
| [Enabling Large Language Models to Generate Text with Citations（ALCE），2023](https://arxiv.org/abs/2305.14627)；[ARES，NAACL 2024](https://aclanthology.org/2024.naacl-long.20/) | 引用质量、RAG 自动评价 | 引用正确不必然代表期间、操作数或数值正确；模型裁判不替代计算金标准 |
| [Confidently Wrong: Detecting Hallucinations in Financial Question Answering from LLM Internal States，2026 预印本](https://arxiv.org/abs/2607.11414) | 在 FinQA/TAT-QA 上用内部状态探针识别错误，并对比输出置信度 | 轻量金融错误检测也已有直接近邻；应加入探针/置信度基线 |
| [VeriFin: A Neurosymbolic Framework for Verifying LLM-Generated Financial Claims，2026 预印本](https://arxiv.org/abs/2608.10213) | 将操作数绑定到 XBRL，核对公式，以 Z3 验证、拒绝或修复 | 期间、单位、公式验证与拒答已被明确覆盖，是最重要的撞题检查对象 |
| [Financial Evidence Crowding: Diagnosing and Mitigating Constraint-Induced Displacement in Retrieval-Augmented Generation（FinDeCrowd），2026 预印本](https://arxiv.org/abs/2609.35782) | 金融证据竞争，以及期间、分部、指标和表格作用域等条件 | 简单加入金融类型规则或按规则重排证据不足以证明创新 |
| [Calibrated Selective Classification，TMLR 2022](https://arxiv.org/abs/2208.12084)；[AbstentionBench，2025](https://arxiv.org/abs/2506.09038) | 选择性预测、风险与覆盖率、拒答评测 | 仅调高阈值、少回答一些问题不算新方法 |

**建议研究的具体增量：非结构化表文场景下，对“证据绑定错误”进行有监督建模，并把绑定的不确定性传递到选择性回答。**它与 VeriFin 的结构化 XBRL＋符号验证路线不同，但“不同输入”本身仍然不够，必须证明新机制优于可迁移的符号/规则校验。

可形成两个相互支持的研究模块：

1. **证据绑定的一致性学习。**为每个操作数输出来源 ID、行列/文本跨度、期间、单位、口径。基于训练集构造最小反事实对：保持算式能执行，只替换年份、单位或作用域；同时加入语义等价的单位换算、表格重排作为应保持判断不变的样本。学习识别“算对但用错证据”，而不是只识别异常字符串。
2. **绑定不确定性驱动的接受控制。**结合多个可行证据绑定、操作数校验结果及计算执行结果，学习接受分数；在独立验证集校准阈值。分析证据选择不确定性与算术错误是否需要不同处理，并在未见公司、期间或扰动类型上测试。

这是拟研究机制，尚未训练。只有它在相同生成器、相同候选答案和相同覆盖率下，优于规则验证、普通正确性分类器及内部状态探针，才能支持方法贡献。若效果仅来自多生成几次或引入更强生成器，需要撤回相应创新结论。

### 3.3 数据、划分与实际可用性

| 数据 | 本次核验 | 实验用途 | 注意事项 |
|---|---|---|---|
| [FinQA 官方仓库](https://github.com/czyssrs/FinQA) | 下载 `test.json`，1,147 题；存在 `program`、`exe_ans`、`gold_inds` 等标签 | 主训练/验证/测试；执行准确率与证据诊断 | 按官方划分获取训练、验证数据；端到端输入须排除答案、解释、gold_inds 及预选 gold 上下文 |
| [TAT-QA 官方仓库](https://github.com/NExTplusplus/TAT-QA) | 下载公开测试金标，277 个上下文、1,663 题 | 第二主数据集，考察表文混合与单位尺度 | 官方测试金标已发布；`derivation`、`facts`、`mappings` 等只能作监督/评测，不得泄露到测试输入 |
| [FinanceBench 官方发布](https://github.com/patronus-ai/financebench) | 下载 150 条公开问答，涉及 32 家公司 | 小规模外部验证、人工错误分析 | 论文描述的 10,231 问并非全部公开；发布集较小，不适合用微小差异宣称普遍优越 |
| [T2-RAGBench，EACL 2026](https://aclanthology.org/2026.eacl-long.8/)；[当前数据页](https://huggingface.co/datasets/G4KMU/t2-ragbench) | 核对页面及文件目录，未下载全量 PDF | 后期真实全库检索扩展 | 当前摘要更新为 23,088 问、约 7,300 文档，但页面旧规模表仍有不同统计；须固定版本后自行统计 |

FinQA/TAT-QA 原始局部上下文问答与全库 RAG 是不同设置。报告和论文要分别命名、分别评分：局部上下文实验验证回答机制；真实检索实验验证检索输入下的可靠性。不能把直接提供 gold evidence 的结果写成端到端检索成绩。

T2-RAGBench 重组了 FinQA、ConvFinQA 和 TAT-DQA 等来源；使用其 FinQA 部分时，与原始 FinQA 不是独立外部数据。需按原始题目 ID、公司报告及文档检查交叉泄漏，禁止随机混合后声称跨基准泛化。[数据来源与当前版本说明](https://huggingface.co/datasets/G4KMU/t2-ragbench)

**新增标注工作控制在可承担范围内：**先对验证集 100～200 个真实模型错误做双人分类，确认“错误期间/单位/口径/证据绑定”确实有足够实例。自动反事实主要从训练集生成；测试压力样本按原始文档分组隔离并人工抽检。原有证据标注未必穷尽所有正确路径，不能把“与唯一参考程序不同”直接判为不忠实。

### 3.4 可执行实验方案

第一阶段固定一个 4B 生成器，保存所有候选答案和结构化计算过程，后续验证方法共用同一候选池。先做数值型问题，再按原始数据支持扩展到其他答案类型。生成器、检索器和验证器的提升分开归因。

| 实验块 | 具体对照 | 要回答的问题 |
|---|---|---|
| 基础回答 | 直接回答、CoT、PoT/受限计算 DSL、普通金融 SFT | 计算执行之外还有多少错误 |
| 接受控制 | 输出概率、自评、采样一致性、规则操作数校验、同容量二分类器；可复现的内部状态探针 | 绑定建模是否提供额外信息 |
| 强近邻 | VeriFin 原始可运行部分；不具备 XBRL 时另设清楚标注的表文规则/符号验证改编 | 收益是否超过已有验证路线；改编不能冒称原论文复现 |
| 主要方法 | 模块一、模块二、二者组合 | 是否存在独立贡献与协同效果 |
| 消融 | 去掉反事实对、去掉期间/单位特征、去掉绑定不确定性、换为普通正确性监督 | 改进是否真的来自提出的机制 |
| 泛化与压力测试 | 官方原始测试；未见公司/报告分组；同值不同口径、等价单位换算、额外干扰证据 | 是否依赖模板捷径，能否保持正确答案并识别真实错误 |

执行计算建议使用有限算子 DSL，并规定数值解析、百分比和单位归一化；拒答样本不能在普通答案准确率里悄悄删掉。删除证据构造的“不可答”仅作为受控压力测试，不可冒称真实自然不可答 benchmark。

### 3.5 指标与研究假设

| 指标 | 定义 / 用法 | 评价地位 |
|---|---|---|
| FinQA Execution Accuracy | 按官方执行评测核对数值；参考程序精确匹配另列 | 主指标之一 |
| TAT-QA EM、F1、scale 相关正确性 | 使用官方归一化和评测实现，按答案类型分组 | 第二主数据集指标 |
| 覆盖率 Coverage | 被接受回答的题数 / 全部题数 | 必须与风险一起报告 |
| 选择性风险 Risk | 被接受但答错的题数 / 被接受题数 | 固定 50%、70%、90% 覆盖率比较，并画完整曲线 |
| AURC | 风险—覆盖率曲线面积；预先固定积分实现和排序方向 | 越低越好；不能替代不拒答时的答案准确率 |
| 错误接受率 | 接受的错误答案 / 全部错误候选；同步报告正确答案拒绝率 | 防止“全部拒答”造成虚假改进 |
| 证据绑定正确性 | 来源、期间、单位、作用域分别评分；结合参考映射和人工核验 | 解释机制；属于扩展诊断，不能声称已有统一标准 |
| 时延、额外 token、显存 | 生成和验证分别记账 | 与质量一起报告 |

**H1：**在相同候选答案池上，证据绑定监督能比单纯算式执行、置信度和普通分类器更好识别证据错配错误。  
**H2：**在相同覆盖率下，不确定性传递能降低真实原始测试集上的错误接受风险；收益能保持到未见公司或扰动类型。  
**H3：**对正确的等价单位变换，方法不会大量误拒绝；对期间/口径替换则更敏感。

预期提高多少分目前没有证据，不填写虚构数值。正式比较使用配对置信区间；同一报告派生多个题目时按报告聚类，避免把相关题目视作完全独立样本。FinanceBench 的 150 题主要用于外部可靠性与错误展示，不承担所有统计结论。

### 3.6 资源与开题门槛

**最低实验形态：**4B 模型短上下文推理＋轻量验证器；必要时 QLoRA 训练绑定输出。单卡 24GB 有望启动，资源瓶颈主要是表文表示和标注，而非必须训练大模型。具体可运行长度须实测，见第 8 节。

进入开题前至少完成：公开评测器跑通；验证集错误审计；PoT＋规则校验强基线；100 个问题的推理资源统计；与 VeriFin/金融探针逐项比较。**如果错误主要是纯算术错误、规则校验已经解决绝大部分目标错误，或方法只在自己构造的模板上有效，就放弃当前创新假设。**

## 4. 主选 B：上下文敏感重排序与预算自适应比较

### 4.1 推荐题目与为什么仍值得保留

**推荐题目：面向长候选列表的上下文敏感重排序与预算自适应比较方法研究——以金融检索为验证场景。**

输入为同一查询的 50/100/200 个候选，输出 Top20。关注某两个文档的比较结果如何受到同批其他候选、输入位置及比较历史影响，以及在有限推理预算下怎样获得稳定且相关的结果。

FiQA 提供真实相关性 qrels，因此排序方法能在不购买商业日志、不自造用户偏好、不依赖模型裁判的情况下进行客观比较。金融是主验证场景；算法是否有效应再用其他检索域验证。不能因为在金融数据上测试，就声称算法本身具有金融创新。

### 4.2 文献审查：原稿的若干创新点已被覆盖

| 工作 | 已有内容 | 必须避开的重复 |
|---|---|---|
| [RankZephyr: Effective and Robust Zero-Shot Listwise Reranking is a Breeze!，2023](https://arxiv.org/abs/2312.02724) | Listwise 重排训练与鲁棒性 | 微调一个更稳的 reranker 不足以形成清楚增量 |
| [A Setwise Approach for Effective and Highly Efficient Zero-shot Ranking with Large Language Models，2023 预印本 / SIGIR 2024](https://arxiv.org/abs/2310.09497) | 集合式比较与高效排序 | 分组比较、堆排序等已有成熟基线 |
| [FIRST: Faster Improved Listwise Reranking with Single Token Decoding，2024](https://arxiv.org/abs/2406.15657) | 使用首个生成位置的标识符概率进行高效重排 | 单 token 解码不是新点；它也不能消除长输入 prefill 成本 |
| [Rank-R1: Enhancing Reasoning in LLM-based Document Rerankers via Reinforcement Learning，2025 预印本](https://arxiv.org/abs/2503.06034) | 推理型 setwise 重排与强化学习 | 加 CoT 或排序奖励不能单独算创新；不要求单卡重做昂贵 RL |
| [LLM-based Listwise Reranking under the Effect of Positional Bias（DebiasFirst），2026 预印本](https://arxiv.org/abs/2604.03642) | 位置倾向校正与均衡位置训练 | 随机打乱和位置均衡不能当成新方法 |
| [Learning from Emptiness: De-biasing Listwise Rerankers with Content-Agnostic Probability Calibration（CapCal），ACL 2026](https://aclanthology.org/2026.acl-short.68/) | 用内容无关输入估计位置先验并校准 | 训练外的位置校准已有直接对照 |
| [Contextual Relevance and Adaptive Sampling for LLM-Based Document Reranking（TS-SetRank），2025 预印本](https://arxiv.org/abs/2511.01208) | 上下文相关性建模和 Thompson sampling 自适应采样 | “不确定性＋主动比较”已经有人研究 |
| [Generate to Accelerate: Improved Reranking via LLM-Generated Pivot Documents，2026 预印本](https://arxiv.org/abs/2604.09492) | 生成参考/支点文档用于截断和重排；较早版本与代码称 DynamicRLT | 通用层次化、锚点校准、动态步长不足以证明新颖性 |
| [Position Bias Undermines Preference Consistency in Listwise LLM-Based Reranking，2026](https://arxiv.org/abs/2608.03091) | 位置偏置导致偏好翻转、循环及不稳定 | 报告排列稳定性或偏好翻转本身不是新贡献 |
| [BoundaryMORPH: Budgeted Reranking via Active Set Selection for Diffuse Retrieval，2026 预印本，under review](https://arxiv.org/abs/2609.27213) | 以 Gaussian Process 和初排先验把 CE 预算用于 Top-K 集合边界 | **“把预算集中在 Top-K 边界”已存在，不能作为本题核心原创宣称** |

论文检索使原稿中的“层次排序＋全局校准＋位置稳健＋短解码”明显需要再收窄。相关工作密集并不意味着完全不能做，但意味着不能只拼接四个已有技巧。DynamicRLT 对应论文最新 v3 已更名，具体早期算法细节本次依据 [v1 全文](https://arxiv.org/html/2604.09492v1)检查；正式复现需再与最新版本和[作者代码](https://github.com/nilanjansb/DynamicRLT)对齐，不能混用版本名与实验成绩。

### 4.3 更具体、仍待验证的方法切口

建议研究：**相关的批次上下文误差如何影响比较证据聚合，以及怎样分配预算来降低这种误差。**区别于把每个文档视为独立、固定相关性得分的简单主动采样，需要显式考虑多个比较受共同批次影响的相关性。

模块一：构造共享候选的配对批次，控制文档位置并改变陪衬候选；利用重复比较估计位置项、批次上下文项及候选间相对偏好。形成可识别的比较图或混合效应模型，并分析需要怎样的共享设计才能分离这些因素。锚点本身已有先例，可能的增量是对**上下文造成的相关误差**进行估计与校正。

模块二：依据估计后的偏好不确定性、上下文误差和 Top20 成员稳定性选择下一次比较，加入停止规则。在同样输入 token 或端到端时延预算下，考察是否比均匀抽样、独立文档不确定性采样及既有边界预算策略更有效。

**尚未证明的关键差异：**TS-SetRank 已研究批次上下文和自适应采样；DynamicRLT 已研究共享锚点；BoundaryMORPH 已研究 Top-K 边界。必须逐条检查拟议概率模型、比较单位、误差相关结构和优化目标，确认不是三者的同义改写。若无法写出实质不同的机制并获得增益，B 不应开题。

一个有价值的反例分析是：同一对文档在不同陪衬候选下发生翻转，但不是所有上下文依赖都属于错误。排序任务中的多样性或覆盖需求可能合理依赖候选集合。本题先固定标准相关性排序目标，避免把两类目标混在一起。

### 4.4 Benchmark 与划分

| 资源 | 可用内容 | 本次状态 | 使用方式 |
|---|---|---|---|
| [BEIR 官方仓库](https://github.com/beir-cellar/beir)；[FiQA 发布页](https://huggingface.co/datasets/BeIR/fiqa) | corpus、queries、qrels | 实际下载 ZIP，57,638 文档，6,648 查询；train/dev/test 为 5,500/500/648 查询 | 主金融实验，训练/调参仅使用 train/dev |
| BEIR 的 SciFact、NFCorpus | 不同检索域及标准相关性标注 | 本次仅确认 BEIR 入口，未下载这两个子集 | 至少选一个作为跨域测试；固定版本后再核验规模和许可 |
| [RankLLM](https://github.com/castorini/rank_llm) | 重排工具及相关基线实现 | 核对仓库 | 复用排名序列、评测与运行配置，锁定代码提交 |
| [LLM Rankers](https://github.com/ielab/llm-rankers) | pointwise/pairwise/setwise/listwise 等实现 | 核对仓库 | 优先复用 setwise 基线；旧依赖需要适配 |
| [Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) | 官方小型相关性重排模型 | 核对模型卡，未下载权重 | 强 pointwise 对照，不能只和 BM25 比 |

FiQA 主要是英文金融问答相关性检索，**不是基金推荐、中文财报搜索或用户点击数据**。qrels 有稀疏标注，未标注文档不等于客观不相关；排名指标按标准协议计算，同时如实讨论判断覆盖的限制。

所有方法使用相同初排候选 ID。先固定 BM25，再增加一种 dense 召回；报告初排 Recall@100/200，因为重排无法找回根本没有进入候选集的相关文档。随机打乱同一候选集合用于稳健性实验，不能同时更换候选内容而归因于位置。

### 4.5 实验、指标与算力闭环

建议从 N=100、窗口 10/20 启动，随后测 N=50/100/200、K=20。先对 dev 查询做预实验，锁定提示词、预算、停止条件后才评测 648 个 test 查询。最终主配置至少 3 个随机种子，稳健性分析用预先固定的 5 组排列；不要求把全部模型、预算、窗口和随机排列做完整笛卡尔积。

| 类别 | 必做内容 |
|---|---|
| 传统与强模型基线 | BM25 初排、固定 dense 初排、Qwen3-Reranker-0.6B 等强 pointwise 对照 |
| LLM 排序基线 | pointwise、setwise、滑动窗口 listwise；可获得权重的 RankZephyr/FIRST 设置 |
| 直接近邻对照 | CapCal、DebiasFirst 可复现设置；TS-SetRank/主动采样策略；DynamicRLT；BoundaryMORPH 的预算分配思想或可运行实现 |
| 公平性条件 | 校准是否额外调用模型、文本截断、预处理、缓存、生成解释、首轮预热等全部记账 |
| 消融 | 无上下文项、只位置校准、独立不确定性、均匀采样、去掉共享比较、固定而非自适应停止 |
| 诊断 | 批次组成与位置分别干预，比较图连通性、偏好循环、不同初排器、不同候选长度 |

若某最新方法未公开代码或其训练预算超出可用资源，明确写“按论文构造的策略对照”并记录差异。不要把小模型改编结果当成对原方法的完整复现；核心方法最好先建立在同一冻结小模型上，以隔离算法增量。

| 指标 | 具体要求 |
|---|---|
| nDCG@10 | 主相关性指标，使用 BEIR 标准评测 |
| nDCG@20、MAP/Recall | 补充；Top20 输出对应 @20，召回阶段另报 Recall@100/200 |
| Top20 集合 Jaccard、nDCG 排列方差 | 同查询、同候选的不同排列间计算；稳定但错误的排序仍可能得高稳定性 |
| 偏好翻转率、循环比例 | 解释误差机制，承认已有研究采用类似诊断 |
| 输入/输出 token、GPU 秒/查询、P50/P95 时延 | 评价预算；跨 pointwise/listwise 不能只比较调用次数 |
| 峰值显存、失败率、ID 合法率 | 可部署性诊断；ID 去重和语法校验是工程配套 |

**H1：**剥离共同批次误差后，在等预算下能提高相关性，同时降低排列敏感性。  
**H2：**考虑相关误差的采样优于独立不确定性采样，并在另一个检索域保持收益。  
**H3：**收益在 N=200 时仍可观，而非只在几十个候选的简化列表成立。

N=200 且每个候选约 200 token，仅正文就约 40,000 token。单卡 24GB 不应以整列表长上下文训练为最低方案。采用窗口比较、缓存初排特征、短输出即可建立实验；FIRST 类短解码主要节省输出部分，并不让长输入变成免费。[FIRST 论文](https://arxiv.org/abs/2406.15657)

**开题门槛：**先用 dev 上 100 个查询验证上下文/位置误差确实存在，跑通 pointwise＋setwise＋校准/主动采样基线，完成等 GPU 时间曲线。若改进仅比 BM25 好、仅靠更多调用，或与 TS-SetRank/BoundaryMORPH 没有可辨识机制差异，暂缓此题。

## 5. 备选 C：任务—约束解耦与组合泛化

### 5.1 推荐题目和需要先验证的现象

**推荐题目：面向金融多任务生成的任务—约束解耦与组合泛化方法研究。**

固定少量有金标准的金融任务，研究共享小模型学习输出约束时，是否损害任务内容，以及约束能否迁移到未见任务—约束组合。例如情感分类要求固定标签，实体抽取要求限定类型与证据位置，数值回答要求答案、单位和证据字段同时正确。

重点不是做一个覆盖 FinBen 所有任务的“统一金融大模型”。需要先观察到可重复的内容—约束干扰，再研究机制。仅修复 JSON 格式、换任务采样比例或增加一个 LoRA，通常不足以支撑题目中的创新。

### 5.2 相关研究与具体增量

| 工作 | 关联与创新限制 |
|---|---|
| [PIXIU，2023](https://arxiv.org/abs/2306.05443)；[FinBen，2024](https://arxiv.org/abs/2402.12659) | 金融指令训练、任务集合与评测已有基础；做多任务金融 SFT 本身不是新贡献 |
| [Gradient Surgery for Multi-Task Learning（PCGrad），2020](https://arxiv.org/abs/2001.06782)；[Conflict-Averse Gradient Descent（CAGrad），2021](https://arxiv.org/abs/2110.14048) | 梯度冲突处理已有经典方法，直接套用只能作为对照 |
| [Beyond Full Fine-tuning: Harnessing the Power of LoRA for Multi-Task Instruction Tuning，LREC-COLING 2024](https://aclanthology.org/2024.lrec-main.206/) | LoRA 容量与多任务泛化已被系统研究，需排除只是 rank 调大带来的收益 |
| [Mixture-of-LoRAs: An Efficient Multitask Tuning for Large Language Models，2024](https://arxiv.org/abs/2403.03432) | 分领域适配器和路由用于减轻干扰；模块拆分本身不足以证明新颖性 |
| [银瞳：基于自适应语义空间学习的中文金融多任务大模型，CCL 2024](https://aclanthology.org/2024.ccl-1.74/) | 中文金融多任务、自适应语义空间和混合专家的直接近邻 |
| [Instruction-Following Evaluation for Large Language Models（IFEval），2023](https://arxiv.org/abs/2311.07911) | 使用可验证约束评价指令跟随；规则检查不是新想法 |
| [From Complex to Simple: Enhancing Multi-Constraint Complex Instruction Following Ability of Large Language Models，EMNLP Findings 2024](https://aclanthology.org/2024.findings-emnlp.637/) | 多约束训练与泛化已有先例；构造约束组合不是自动获得新颖性 |
| [Generalizing Verifiable Instruction Following（IFBench），2025](https://arxiv.org/abs/2507.02833) | 专门研究未见约束的泛化，需作为重要方法近邻和外部验证资源 |
| [RECAST: Expanding the Boundaries of LLMs' Complex Instruction Following with Multi-Constraint Data，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/69f00d007e2447997120b1c41dea741b-Abstract-Conference.html) | 多约束合成、验证与强化学习训练，需避免只重复数据构造路线 |

可研究的增量应落在：**内容监督与约束监督怎样被定位、隔离和协同更新，以及这种设计是否能保持未见组合的内容正确性。**

建议模块一把内容字段与约束字段的损失、梯度影响分开记录，分析什么约束导致哪类任务退化；模块二尝试共享约束表示与任务内容适配的分解，只在出现有证据的冲突时调整更新。需要在相同参数量、相同训练 token 下与单一 LoRA、任务专用 LoRA、Mixture-of-LoRAs 及梯度方法比较。

这种分解是候选设计，不是已经确认的新算法。若“两个 LoRA＋PCGrad”足以复现全部收益，就不能把重新命名后的组合当成主要贡献。更值得研究的是**未见组合下内容与约束的联合泛化机制**，以及它对预算和任务结构的依赖。

### 5.4 组合泛化实验怎样避免标签泄漏

先划分内容实例，再扩增约束；同一句、同一报告的不同格式版本不能分散到 train 和 test。保留一组“训练见过任务和约束，但没见过二者组合”的测试；另外设置未见约束测试。二者分别对应组合泛化和约束泛化，不能混称。

训练数据中的目标由原标签确定性转换产生。约束若不能与原标签同时满足，就应剔除或进入单独的不可满足约束实验，不要默认模型必须输出一个正确答案。例如要求“输出全部实体且恰好一个实体”，在多实体句子上本身不成立。

[IFEval 官方实现](https://github.com/google-research/google-research/tree/master/instruction_following_eval)和[IFBench 官方资源](https://github.com/allenai/IFBench)分别已下载核验 541 和 300 条测试输入，用作通用外部指令泛化补充。IFBench 的测试约束、公开训练资源各有用途，测试题及其改写不能进入训练；它们也不能直接证明金融内容正确性。

### 5.5 基线、指标、消融与停止条件

| 类别 | 设计 |
|---|---|
| 基线 | 单任务 SFT、等训练 token 的混合 SFT、任务专用 LoRA、容量匹配的多 LoRA、PCGrad/CAGrad、多约束数据训练 |
| 关键强基线 | **语法约束解码＋普通内容 SFT**；适用时加确定性字段转换。这是检验“训练方法是否真的必要”的对照 |
| 消融 | 不区分内容/约束损失、不做冲突处理、不共享约束表示、随机而非冲突驱动调度；适配器总 rank 匹配 |
| 内容指标 | 情感 Macro-F1；NER 实体级 span F1；FinQA Execution Accuracy，逐任务报告 |
| 约束指标 | 每个约束满足率、全部约束同时满足率，验证器固定并公开 |
| 联合指标 | `内容正确 AND 全部约束满足` 的比例，以及内容质量—约束满足率 Pareto 曲线 |
| 泛化指标 | 已见组合、未见任务—约束组合、未见约束分别报告；原始无额外约束能力另测 |
| 代价 | 可训练参数、总训练 token、GPU 时数、推理开销 |

混合任务的 F1、执行准确率、摘要分数不能不加说明直接求平均。NER 的“实体集合完全正确率”可作严格联合指标，但必须同时保留标准 span F1，以免不同任务难度被掩盖。

**H1：**负迁移来自可定位的内容—约束更新冲突，而非仅训练 token 不平衡或模型容量不足。  
**H2：**在总参数量与数据预算一致时，拟议分解提高未见组合的联合正确率，同时保持原始任务能力。  
**H3：**收益超过纯语法约束解码，出现在证据区间、单位尺度等带内容语义的约束上。

**放弃条件：**均衡采样后负迁移不复现；容量匹配 LoRA 已消除差异；所有收益只是 JSON 合法率；未见组合优势不超过简单转换/解码基线。满足这些情况时，C 不宜作为“方法创新”的硕士主选。

## 6. 为什么暂不选择另外三个方向

### 6.1 原方向一：基金推荐论据生成

这条路线最贴近实习，但目前最难保证独立评测。基金公开字段可以核对事实，却不能直接回答“这一理由对这一用户是不是有用”“推荐是否适当”“证据多样性是否提高决策质量”。由教师模型生成需求和理由，再由同类模型判好坏，容易形成循环评价。

相关研究已经覆盖个性化解释与自动评价：[PETER，ACL 2021](https://aclanthology.org/2021.acl-long.383/)、[ALERT，NAACL 2025](https://aclanthology.org/2025.naacl-long.137/)。[FIRE，2025 预印本](https://arxiv.org/abs/2508.05225)研究基于属性贡献的忠实解释；[A Necessary Step toward Faithfulness，EMNLP 2025](https://aclanthology.org/2025.emnlp-main.797/)研究预测与自由文本解释的一致性。证据选择与偏好训练需要对照这些工作，而非仅与普通 SFT 比较。

另一个直接相关预印本 [Beyond Factual Correctness…（PURE）](https://arxiv.org/abs/2603.03080)在 2026 年 5 月撤稿，作者说明特征提取和语义匹配评测协议需要修正。它不能作为已验证的效果依据；这也提示评价协议本身会成为此类研究的重大风险。

**重新进入候选的条件：**能取得可公开、独立标注的需求—基金—证据/理由集合；由至少两名独立评审标注并报告一致性；按产品与时间隔离；主要评价不依赖生成标签的教师。Amazon 商品解释可验证方法在商品域上的效果，但不能替代金融用户偏好的真实性验证。若这些条件不具备，本题更适合作为应用原型或后续扩展。

### 6.2 原方向五：基金多属性语义检索

该题的核心缺口是 qrels。公开基金持仓、规模、收益等属性不是“某个自然语言需求对应哪些相关产品”的独立标签。若自己设计属性权重、用该权重产生正负样本、再训练模型拟合，就只能证明模型学习了这套规则，难以证明改善真实语义检索。

重启条件是先构建并公开有独立评审的查询—产品相关性标注，给出争议处理、时间快照、产品类型划分及标注一致性。不能用商业 CTR 的设想代替当前可取得的实验材料。对当前资源约束，更建议把检索方法放到 B 的成熟 qrels 上验证。

### 6.3 原方向六：层次意图识别与工具路由

[BANKING77](https://huggingface.co/datasets/PolyAI/banking77)的任务是银行意图分类；它没有完整工具轨迹、参数金标和执行环境。从分类标签映射到自设工具，只能评价自设映射，不能直接验证真实金融工具调用。

本次找到较新的 [FinToolBench: Evaluating LLM Agents for Real-World Financial Tool Use，2026](https://arxiv.org/abs/2603.08262)，并实际核对其[公开仓库](https://github.com/Double-wk/FinToolBench)：问题文件 295 条，工具文件 760 条。**它确实有公开资源，不能再说“完全没有金融工具基准”。**

但公开版本主要提供评测、数据及运行辅助，完整 Agent 训练和构建流程没有全部发布；工具涉及 RapidAPI、AKShare 等外部服务，账户、调用额度、网络及实时数据变动影响复现。工具文件里的函数代码是运行定义，不等于已验证的可用环境；本次没有执行这些代码。其 SoftScore 等模型裁判分数也需要与参数/执行正确性区分。

若能先冻结一套离线工具、输入输出快照及参数真值，可以另拟“离线金融工具选择的成本敏感决策”题目；但这会增加环境建设工作，且离线改编成绩不能冒称原 FinToolBench 实时成绩。当前不把它列入最稳的前三个毕业路线。

## 8. 显卡资源：哪些方案能启动，哪些不应作为前提

模型先选[官方 Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B)，锁定 revision、推理模式和生成上限；B 增加强 pointwise reranker。是否开启 thinking 要对所有对照统一，并记录由此带来的 token 和延迟。暂不把 70B、超长上下文训练或在线 RL 当作最低毕业条件。

4-bit 量化和 QLoRA 使小模型训练更容易进入单卡预算，但并不只占“参数量 × 0.5 字节”。激活、量化元数据、优化器、KV cache、序列长度及批次仍然占显存。[Transformers bitsandbytes 文档](https://huggingface.co/docs/transformers/quantization/bitsandbytes)、[LLaMA-Factory 资源估算与训练说明](https://github.com/hiyouga/LlamaFactory)

以下为**规划配置与可行性判断，不是实测显存或完成时间承诺**：

| 资源 | 建议安排 | 需要实测 / 降级的部分 |
|---|---|---|
| 单张 12～16GB NVIDIA | 0.6B reranker、小型验证器；4B 量化短上下文推理，视情况尝试 QLoRA | 训练与多候选采样余量较小，长序列需裁剪/分块 |
| **单张 24GB NVIDIA，当前预算假设** | 4B 4-bit QLoRA 起步，序列 2k～4k、micro-batch 1、梯度累积和 checkpointing；A/C 小模型训练，B 窗口推理 | 实测后确定 LoRA rank、最长序列和批次；不能保证所有 8B/长上下文配置都能运行 |
| 48GB 或多张可稳定使用的卡 | 增加 7/8B 对照、更长上下文或更快吞吐 | 总实验量仍应聚焦，不必因显存增加而扩成全部金融任务 |
| 没有稳定 GPU | B 的传统/小型排序初步实验、数据和评测开发可在 CPU 开始 | LLM 主实验需要明确的租用或实验室排期；当前三条路线不能假定 CPU 足够完成所有训练 |

主机内存建议至少 32GB，64GB 更方便缓存索引与数据；预留约 50～100GB SSD 作为小模型权重、环境和实验输出预算。这是工作空间规划值，实际取决于保存的模型数和 checkpoint，不是公开数据本身必需占用这么多。

**先测再估算 GPU 时数：**

1. 使用实际显卡、最终依赖和候选配置，跑 100 个训练 step，记录有效 token/step、GPU 峰值显存、秒/step；另跑 100 个验证问题/查询，记录输入输出 token 和 P50/P95 时延。
2. 训练预计时数 = `计划 optimizer step 数 × 实测每 step 秒数 ÷ 3600`。不同方法的多任务梯度计算、采样与额外验证分别测，不能一律套普通 SFT 速度。
3. 评测预计时数 = `测试查询数 × 每查询比较/采样次数 × 单次实测时间 ÷ 3600`，或直接用整查询流水线速度外推。计入排列重复、强基线和消融，分别记录冷启动与缓存设置。
4. 以稳定可用时数安排主实验；若排期不足，先减少模型规模和探索配置，保留核心强基线、主数据集、消融和随机种子，不能只保留最有利结果。

Windows 可以先做下载、清洗与评测；训练栈选择取决于 CUDA、量化库和注意力实现兼容性。需要时使用 Linux/WSL2，不在未测试前承诺本机一键训练。当前没有显卡速度或价格数据，因此不提供虚构的“几百元必做完”预算。

## 9. 两周预实验与 3～6 个月单题进度

建议以 **A 为主预实验，B 做较小并行诊断，C 保留方案**。这里是研究安排，不表示本次已经执行这些模型实验。两周后选定一个主问题，不同时推进三篇论文。

| 阶段 | A 必做 | B 必做 | C 的进入条件 |
|---|---|---|---|
| 第 1～3 天 | 跑通官方数据与数值评测；生成基线候选池 | 固定 FiQA 初排与候选；跑小型 pointwise | 确认三任务数据划分与目标转换 |
| 第 4～7 天 | 审计 100～200 个 dev 错误；PoT＋规则验证 | dev 上固定候选，改变位置与批次；setwise 基线 | 混合 SFT 相对单任务产生可重复退化 |
| 第 8～10 天 | 轻量绑定验证器；风险—覆盖率曲线 | 位置校准/主动采样对照；预算曲线 | 排除采样不均、容量不足和纯 JSON 原因 |
| 第 11～14 天 | 检查与 VeriFin/探针的实质差异和泛化迹象 | 检查与 TS-SetRank、DynamicRLT、BoundaryMORPH 的差异 | 未见组合问题确实存在且无法靠简单转换解决 |

建议预先约定继续/停止依据，避免后验挑分数：A 必须在原始问题错误上表现出绑定监督的额外价值；B 必须在等预算下有超过强基线的相关性或质量—成本收益；C 必须在语法解码之外提高内容—约束联合正确性。预实验用于发现问题和选配置，正式结论在预先保留的测试集上验证。

选定单题后可按下列阶段推进，阶段长度按实际 GPU 时数调整：

| 时间 | 产出 |
|---|---|
| 第 1 月 | 近邻全文对照表、可运行强基线、固定数据/评测协议、资源实测、开题问题定义 |
| 第 2 月 | 第一个方法模块；错误机制分析；开发集消融 |
| 第 3 月 | 第二个模块；正式主数据集评测；质量与代价曲线 |
| 第 4 月 | 第二数据集/第二模型或跨域验证；统计分析；失败案例与局限 |
| 第 5～6 月，若有 | 补关键复现、整理代码与材料、撰写修改；避免无限追加无关任务 |

对计算机技术硕士，A 可以组织为“证据绑定一致性学习”和“选择性回答决策”两章；B 为“上下文误差建模”和“预算比较决策”；C 为“干扰诊断与解耦学习”和“组合泛化”。章节安排服务于一个中心问题，不能用两个无关工程模块充当两项创新。
