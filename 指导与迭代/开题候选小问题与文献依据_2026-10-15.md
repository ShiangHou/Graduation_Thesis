# 开题候选小问题与文献依据

日期：2026-10-15。状态：问题筛选，尚未定题。

本轮纠正：当前需要从文献中寻找“特定任务下，特定方法在特定条件下发生的具体错误”。不预先承诺候选组成鲁棒性、一致性训练或业务方案。此前的预实验建议保留为讨论历史，不代表已确定研究路线。

阅读范围说明：本轮对相关论文的问题定义、方法、实验、失败分析和局限做了针对性阅读，深度不一；不能称为全部论文逐页精读或穷尽检索。以下将论文已有结论与我们提出的问题边界分开。预印本结论仍需复核。

## 1. 长文档重排：关键证据位置变化后的相关性误判

问题句：在查询相关证据位于文档中后部、且证据实际进入模型输入的长文档重排任务中，整篇输入的重排模型可能低估相关文档；如何缓解这种位置依赖？

直接依据：[Positional Bias in Long-Document Ranking: Impact, Assessment, and Mitigation](https://arxiv.org/html/2207.01262)，§3.3、表2、§5。论文在 FarRelevant 上观察到包括所测试 RankGPT 配置在内的模型表现不佳；MaxP、PARADE Attention 等方法提供了重要对照。去偏训练的收益不一致，部分模型改善位置变化测试却损伤原始分布性能。

更细的研究切口：位置去偏造成的原分布排序能力退化。不过该训练结论主要来自传统交叉编码模型，不能直接写成“现代 LLM reranker 已被证明存在同样训练退化”。选择此切口时需要继续核对 LLM 上的直接证据。

边界：这是单篇文档内部证据位置，不是候选文档之间的顺序；排除证据被截断；不能把打乱句子造成的语义破坏当作纯位置影响。FarRelevant 是合成诊断集，其连贯性局限不能忽略。创新不能仅是切块后取最大值。

候选题目：《面向长文档重排的相关性证据位置偏置缓解方法研究》。这是与原长序列方向衔接最自然的候选，但仍须继续聚焦具体模型与改进机制。

## 2. 排除约束重排：把“顺带提及”误当成“违反约束”

问题句：在含明确排除条件的检索任务中，基于整篇文档与排除意图相似度的惩罚式重排，会误降序那些满足需求、仅顺带提及被排除概念的文档。

直接依据：[E-SENS](https://arxiv.org/html/2608.30130)，§3、§6、Limitations。它用 LLM 分解查询，再扣减排除意图相似度；失败分析明确指出文档级惩罚不能区分顺带提及与真正违规，并提出片段级核验作为未来方向。这是预印本中的定性失败证据，尚不能推断问题发生率。

示意例子（自拟）：查询“介绍不使用强化学习的语言模型训练方法”；有效文档介绍监督微调，背景段提到强化学习；违规文档主要介绍强化学习训练。研究目标是区分二者，而非禁止出现某个词。具体标注必须尊重查询语义：“排除主题”和“禁止任何提及”不是同一个约束。

近邻：[NS-IR](https://arxiv.org/html/2505.22299) 已做逻辑约束处理；[CoDeR](https://arxiv.org/html/2606.13204) 已将主题相关性与约束兼容性分开建模。因此“加入约束判断”本身不是新贡献。

重要边界：E-SENS 是 LLM 辅助查询分解加向量分数重排，不是 LLM 直接读文档打分。不能把该失败未经验证地归给所有 LLM reranker。若坚持研究 LLM 直接重排，此项目前是候选假设。

候选题目：《面向排除约束检索的文档重排误惩罚缓解方法研究》。问题粒度很合适；研究空间应限定在有效文档被误伤，而不是整个否定理解领域。

## 3. 带日期文档重排：与查询无关的发布日期干扰相关性判断

问题句：在查询不要求时效性的文档相关性重排中，LLM 因发布日期较新而系统性抬高候选文档，导致排序受无关元数据干扰。

直接依据：[Do Large Language Models Favor Recent Content?](https://arxiv.org/html/2509.11353)，§3–5。该文固定正文、注入人工发布日期，考察列表重排及成对偏好。它支持“日期会引发系统性排序偏移”；同等相关文档之间换序不必然意味着检索质量下降，应区分偏好与实际损害。

潜在切口（我们的推论）：按查询是否需要时间信息，抑制无关日期线索的干扰。不能仅删除日期后宣布解决，因为有些查询确实需要时间信息；若限定全部查询均不涉及时效，直接屏蔽日期则是必须正面超过的简单方案。

直接近邻：[FRESCO](https://arxiv.org/html/2604.14227) 已研究动态事实冲突，并通过指令优化权衡动态与非动态知识任务。因而“平衡时效性和相关性”不是空白。更窄的候选是发布日期与证据有效性不一致时的误判；其原创空间尚待进一步查证。

候选题目：《面向非时效查询的 LLM 文档重排日期偏置缓解方法研究》。技术边界清楚，但简单基线和 FRESCO 都可能压缩方法空间，列为备选。

## 4. 为什么暂不优先选择笼统的顺序稳定性

[Equal Ranking Quality, Different Decisions](https://arxiv.org/html/2608.26762) 已研究共享提示内批量评分的顺序依赖，提出 OC-SFT；附录 C.1 还研究候选集合变化和编号重命名。尤其要注意：普通顺序一致性未迁移到编号变化，但论文已经加入编号一致性惩罚并报告改善。因此不能再把“加入编号一致性损失”作为未做过的建议。

[OLR-Heads](https://aclanthology.org/2026.findings-acl.1743/) 在数据库及工具选择中处理编号、位置和顺序敏感性；它不是直接证明完整文档重排已解决，但属于必须比较的近邻。

已有人研究不等于不能写硕士论文。问题可以沿用，贡献需要明确优于什么已有方案。当前不推荐直接题为“LLM 重排稳定性优化”，因为还没有指出既有去偏方法在哪个具体条件下不足。

## 当前判断

若保留 LLM 与长序列主线，优先深挖第一项；若允许转向更一般的重排方法，第二项的问题描述最具体；第三项作为备选。这里的优先级是阅读和开题讨论优先级，不是对创新性已经成立的保证。

开题应先写一句可核查的问题陈述，再梳理最近的解决方法及其局限。不要同时把解释机制、提出算法、解决业务三件事写成三个并列大问题，也不要在问题尚未确定时先堆出多个算法模块。

对上游质疑的边界：研究给定候选集合中已存在有效证据时，重排器为何仍误排序。上游质量影响整体系统上限，但并不消除上述排序错误；不承诺重排恢复未召回文档。
