# 实验方案与论文撰写流程

整篇论文的完整主方案见 [论文完整研究与撰写方案](论文完整研究与撰写方案.md)，包含明确题目、问题与创新、连续文献综述、算法设计和七章写作安排。本文件作为实验资源与流程的专项附件保留。

版本：2026-10-10。资源约束：无独立人工标注者、拟单卡 24GB、整篇论文 3–6 个月。本文中的训练配置、耗时和性能门槛均为**待实测计划**；已完成事项仅指数据下载、字段与划分审计、官方指标自检。

## 1. 实验问题与最小范围

主任务：给定财报表格／文本、数值问题和冻结生成器的候选答案，预测错误风险，选择回答或拒答。最小版本不处理原始 PDF/OCR，不扩展检索系统，不建设大型财务指标知识图谱。

主数据：FinQA 全部程序题、TAT-QA 的 arithmetic 子集。count 和可规范化的数字 span 可作次要扩展，必须分别给出规模与筛选规则；非数值 span 不混入主结果。英语数据并不妨碍中文学位论文，若学校要求中文应用再增加扩展。

因果比较原则：**先固定候选答案，再比较验证与选择方法**。如果某方法重新生成了答案，它属于另一个完整系统实验；不得把其提升全部归因于验证器。

清单：[split_manifest.json](split_manifest.json)；统计：[split_summary.json](split_summary.json)。这是一套已生成的**拟用拆分**，并不意味着模型已经训练。若后续改变，应升版本并保留旧清单。

为什么要留 S：在生成器已经训练过的题目上训练风险头，会让正确率与错误分布偏乐观；独立留出的 S 更容易解释。若样本明显不足，可将 G/S 做交叉拟合，但会增加多次生成器训练成本，3 个月版本先不做。

### 3.1 关于“独立测试”的具体边界

- FinQA 的 G/S/V/B 之间报告组互斥，但官方 C/T 与原 train 仍有报告重叠。本协议可与原基准对齐，**不具备报告级完全独立保证**。
- TAT-QA 仅验证了 table uid 不重叠，没有完整公司／财报元数据，不能把它称为跨公司实验。
- 6 个月版本可另做 `report-disjoint` 实验：从 FinQA 原 train+dev 报告组重分 G/S/V/C/T，单独训练模型并报告自定义测试规模；这组实验不与官方 test 成绩混称。也可另报告官方 test 中未在训练出现的报告子集，但其样本较小。
- FinanceReasoning 中 795 条 CodeFinQA-test 与 288 条 CodeTAT-QA-test 必须单列；不同表述和编号不代表独立语料。
- GBFR 的反事实题与母题保持同组，不能将 test 母题的改写用于 S/G。问题文本相同不能单独证明同一样本，正式连接需进一步比对上下文和源 ID。
- 开源模型预训练是否见过公开基准无法完全排除；以新扰动、跨生成器／报告诊断评估稳健性，避免声称完全排除预训练污染。

## 4. 输入、标签与安全执行

### 4.1 统一输入和输出格式

所有方法使用相同可见文档，保留表格结构、坐标和正文位置。结构化输出示例：

```json
{
  "sample_id": "dataset:question-id",
  "answer": "12.5",
  "scale": "percent",
  "program": [{"op": "divide", "args": ["r1", "r2"]}],
  "operands": [
    {"role": "r1", "source_id": "table:2:1", "value": "25"},
    {"role": "r2", "source_id": "table:3:1", "value": "200"}
  ]
}
```

此例仅演示格式，实际 percentage 乘 100 的语义必须在 DSL 或尺度层统一定义。源码坐标与数值对不上的输出应记录为解析／绑定失败，而不是静默修正后记为原答案正确。

按固定策略处理长输入，记录截断比例；不能根据 gold evidence 选择片段。若完整文档过长，使用统一的、只读问题和可见证据的检索／裁剪；其缺证据情况是系统失败的一部分。Oracle evidence 只做上限分析并单独标注。

### 4.2 哪些标签可直接获得

| 标签 | 获得方法 | 可验证边界 |
|---|---|---|
| 答案对错 y | FinQA 官方执行与 exe_ans；TAT-QA 官方 EM／scale 规范 | 必须明确“程序答案”还是“文本最终答案”的适配方式 |
| 证据集合 | TAT-QA mapping、FinQA gold_inds | 参考证据集合不穷尽所有等价链；FinQA 更粗 |
| 角色—来源匹配 | 参考程序操作数与 mapping/facts 对齐，保留多个匹配 | 不是原始数据直接给出的唯一角色标注；对齐失败率要公开 |
| 算术／类型有效 | 受限执行器检查 | 不等于语义正确；数值相等不等于单位／时期正确 |
| 拒答需求 | 公开已有不可答标签或严格受限诊断 | 原始 FinQA/TAT-QA 主要可答；“模型答错”与“题目不可答”不同 |

注意 FinQA 的 `const_5` 等 token 可能承载题目里的实际值，不能把全部 `const_*` 当作无须证据的数学常量。常量角色规则要依据问题与程序用途定义；常见百分比缩放 100、平均数的计数等也应在记录中说明。

执行器采用算术白名单、引用检查、除零与非有限值检查，保留负号、百分数、千／百万量级。不会直接 `eval/exec` 模型任意 Python。FinanceReasoning 的 python_solution 用作参考文本；如确需执行，其运行必须隔离、无网络且有限时。

### 4.3 DeepSeek 弱标注的具体方案

初次仅取 G 的 300 条，验证标签流程；流程可靠后扩至约 600–2,000 条困难样本。教师收到训练 gold 时必须标记 `teacher_sees_gold=true`。输出原始响应、解析后 JSON、模型标识、时间、prompt hash、token 用量及各过滤原因。

将通过“引用可解析＋执行匹配”筛选的样本用于训练，不能据此宣称其语义证据全部正确。对一对多来源保留候选集合，拒绝伪造单一确定标签。比较三种训练条件：仅公开 gold、加入原始教师弱标签、加入过滤弱标签；保证训练数量或采样预算可比。

API 不参与主测试 gold 判定；不让测试答案进入教师提示。未调用任何付费 API，本轮没有消耗模型服务费用。

## 5. 基线：哪些必须做，哪些需分开比较

### 5.1 固定候选实验的最小基线

| 编号 | 基线 | 同等比较要求 |
|---|---|---|
| B0 | 全部接受、随机拒答 | 显示原始错误率和非信息性参照 |
| B1 | 输出平均／最小 log probability；模型自报置信度 | 相同生成输出；无 logprob 的 API 不强行造该特征 |
| B2 | 自一致性、规范化数值答案熵 | k=4 为最小设置，k=8 做敏感性；记录额外调用成本；保留单位和符号 |
| B3 | 执行有效性＋类型／时期／来源存在性规则 | 这是核心强基线，不能仅与原始 LLM 比 |
| B4 | 同特征 Logistic Regression／小 MLP | 与新方法同标签、同训练集、近似容量；排除“多加特征”解释 |
| B5 | 文本／表格证据支持的 NLI 聚合＋风险头 | SURE-RAG 思路的任务适配；明确是重实现，不能引用其论文分数作本地结果 |
| B6 | 残差状态线性探针 | 参照 Confidently Wrong；冻结生成器，池化层和正则在 V 选；能获取内部状态时开展 |
| B7 | 单一 top-1 绑定验证；独立操作数分布传播 | 与联合绑定构成直接消融，检验结构依赖的实际价值 |
| Ours | 部分监督联合绑定＋执行等价结果＋风险头 | 使用与 B4/B7 相同信息和校准预算 |

三个月最低完成 B0–B4、B7、Ours；B5/B6 至少完成一个，另一个若缺失必须解释原因与结论限制。正式声称超过金融幻觉检测方法时，B6 不应省略。k=4 答案样本可复用于多种不确定性指标，不重复收费或生成。

### 5.2 近邻完整系统如何比较

GBFR 是完整解题系统，需 Neo4j、图谱与兼容 API。首先尝试在 V 的小批量跑通，再在相同文档和预算条件下比较最终答案风险；记录无法执行、超时和缺失公式。不能将其重新生成答案的结果与固定候选验证器混进一张无说明表。若只复现其部分原则，应命名“graph/rule-inspired baseline”，不称完成 GBFR 复现。

VeriFin 的原生 XBRL 与本题非结构化输入不同。可在双方都支持的结构化子任务比较；若自行把方法迁移到 TAT-QA，要清楚写出适配与缺失能力，不把适配失败等同于原方法失败。FinGround 当前资源不可得，保留方法分析，尝试同功能替代基线而非编造复现成绩。

### 5.3 生成器配置

主生成器拟用 [Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B)，固定非 thinking 模式、模板、模型 revision 和推理精度；先零样本／少样本冻结，只有程序格式或准确率成为明显瓶颈才在 G 上 QLoRA。示例只能来自 G。

第二生成器可用 [Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) 的固定量化版本，测试模型代际迁移；它与 Qwen3 仍属同系列，不应称跨模型家族。若通过 API 使用 DeepSeek 作额外候选生成器，记录服务版本与日期，单列无内部状态的条件。不是每个验证器都必须重训第二生成器。

## 6. 指标、统计和评分陷阱

### 6.1 数值任务指标

- FinQA：主报官方 execution accuracy；program accuracy 采用其符号等价评测，仅作次要参考，不以字符串一致替代。
- TAT-QA：官方 EM/F1 和 scale；arithmetic/count 中 F1 基本退化为 EM，应重点给 EM、尺度错误及失败类型。
- 统一输出适配层：明确裸数字、百分数、负数和币种／倍率；主结果保持各自官方规则，可另报跨数据统一的严格数值口径。不能给新方法更宽的相对误差容差。
- 执行成功率、JSON 解析率、source_id 有效率均作为过程指标，不能替代答案准确率。

### 6.2 选择性回答主指标

令错误标签 e_i=1 表示最终答案错误，A_i(t)=1 表示风险分数不超过阈值 t 后接受：

\[
C(t)=\frac{1}{N}\sum_i A_i(t),\qquad
R(t)=\frac{\sum_i A_i(t)e_i}{\sum_i A_i(t)}.
\]

当没有答案被接受，R 记为 N/A，不记为“0 风险优于所有模型”。报告接受数／错误数原始计数。

| 指标 | 用途 | 约束 |
|---|---|---|
| Risk–Coverage 曲线、AURC | 主指标，低为好 | 风险从低到高排序，离散 AURC 为各接受前缀错误率均值；同分处理预先固定，额外报同分组曲线 |
| Risk@50/70/90% coverage | 同回答数量比较 | 测试排序曲线是描述性诊断，不能据测试标签选阈值 |
| Coverage@目标风险 5%、10% | 实际部署工作点 | 阈值在 C 冻结；测试同时报实际风险、覆盖和区间；目标未满足要直说 |
| AUROC、AUPRC-error | 错误排序 | 约定错误为正类；AUPRC 的基线是错误率，跨生成器别直接比绝对值 |
| Brier、ECE | 概率质量辅助 | ECE 固定分箱并给出分箱样本数；不以总体校准代替被接受集合风险 |
| Evidence Recall@k、参考 mapping F1 | B 集机制诊断 | 参考位置只是一组支持证据；不同合法链造成的假错要声明 |
| 额外 token、延迟、峰值显存 | 成本收益 | 缓存预热／未预热、生成／验证耗时分别记录 |

全数据主结果与执行有效子集结果都要报告，不能静默删除解析失败、长输入或低置信困难题。不可答诊断额外报告不可答题误接受率和可答题回答率，原始自然集与反事实集分别汇报，防止调高拒答比例使总指标虚高。

### 6.3 置信区间与“安全保证”

对自然数据的比较，按报告／表格 group 做配对 bootstrap（建议 2,000 次），报告 AURC 差、固定覆盖风险差的 95% 区间；对方法随机性做 3 个训练种子，小型筛选期先 1 个。抽样时衍生题和原题同组。若要估计阈值选择的不确定性，在每个 bootstrap 中重抽 C 并重新选阈值，然后评价重抽 T；否则明确区间仅条件于已定阈值。

建议主论文写“经验风险控制”，而不是“金融答案零风险保证”。独立二项观测下，固定阈值接受 n 个样本且观察到零错时，单侧 95% 上界为 `1 - 0.05^(1/n)`：n=59 才约低于 5%，n=299 才约低于 1%。搜索多个阈值需要额外控制多重选择；同财报问题又非独立，不能直接套用这些数字声称有严格保证。

若研究正式统计保证，应预先固定阈值候选并作同时置信界或使用独立阈值选择／验证集，采用适合组依赖的抽样单位，并写明分布假设。域偏移下不自动保持保证。[COIN](https://arxiv.org/abs/2506.20178)、[Conformal Risk Control](https://proceedings.iclr.cc/paper_files/paper/2024/hash/f3549ef9b5ff520a7e41ff3cc306ab2b-Abstract-Conference.html)。

## 7. 实验清单：每张表要回答什么

| 实验 | 内容 | 必须展示的证据 | 优先级 |
|---|---|---|---|
| E0 | 数据／指标自检 | 当前已运行的样本数、字段、哈希、gold round-trip | 已完成 |
| E1 | 生成器基线 | 两主数据答案准确率、错误率、解析率、证据候选召回 | 开题预实验 |
| E2 | 固定候选选择 | B0–B7 与 Ours 的 AURC／风险覆盖及成本 | 核心 |
| E3 | 结构消融 | 无位置／无时期单位／独立绑定／无未知状态／不合并等价结果 | 核心 |
| E4 | 等信息强基线 | 同标签和同特征的 Logistic/MLP 与结构模型 | 核心，防止把特征增量误称结构创新 |
| E5 | 来源定位诊断 | B 集 mapping Recall@k/F1；top-1 与多候选差异 | 核心机制证据 |
| E6 | 扰动稳健性 | 训练外的数值／单位／时期受控扰动；公开拒答集可选 | 核心诊断，标签范围须明确 |
| E7 | 迁移 | 换生成器；FinQA 与 TAT-QA 的分数据表现；校准重用／重新校准分别报 | 至少一个迁移方向 |
| E8 | 预算曲线 | k=1/2/4/8，beam=1/4/16；风险 vs token／延迟 | 3 个月简版，6 个月完整版 |
| E9 | 完整系统近邻 | GBFR 或适用条件下 VeriFin | 先小范围跑通，避免大系统吞掉主线时间 |
| E10 | 严格跨报告／额外数据 | 自定义 report-disjoint、FinanceReasoning 去同源、中文 | 6 个月扩展 |

扰动必须先按原始 group 切分，再在各自划分内生成。数值替换只有在引用坐标、全部受影响事实及答案均能一致更新时才赋自动 gold；财务恒等式可能被破坏，应标为受控算术诊断，不能冒充真实公司事实。无关证据增添应选择本来不承担已知参考角色的位置，但仍不能保证对所有等价解法完全无影响。

误差分析至少区分：题意／公式错、来源错、时期错、单位尺度错、符号错、算术／执行错、截断／缺证据、答案抽取错。可以由作者自己检查典型案例并借助 LLM 提议分类，但不可把这些类别统计标成独立双人标注或提供虚假的一致性系数。

## 8. 单卡资源和费用：先测，再承诺

### 8.1 显存方案

| 路线 | 建议配置 | 适配判断 |
|---|---|---|
| 首选 | 冻结 4B 生成器，4-bit 或 BF16 视实测；短输入；训练小型绑定／风险头 | 最符合 24GB；生成器与验证器可顺序运行 |
| 可选 | 4B QLoRA，长度 2,048 起，micro-batch=1，梯度累积 16/32，checkpointing，rank 8/16 | 有合理可行性；模型、上下文及优化器组合需实际验证 |
| 扩展 | 7B/8B 量化推理或短上下文 QLoRA | 不承诺所有 24GB 卡、所有实现都能跑；速度和注意力缓存可能成为瓶颈 |
| 不选 | 7B 全参数训练、多模型同时驻留、长上下文大 batch、全流程在线 RL | 超出本课题最低资源方案 |

仅权重理论容量：4B 的 4-bit 权重约 2GB，8B 约 4GB；BF16 分别约 8GB、16GB。这些数字**不含量化元数据、未量化层、激活、优化器和 KV cache，不能当作总显存需求**。QLoRA 是成熟技术而非论文创新。[QLoRA](https://arxiv.org/abs/2305.14314)。

远程 GPU 建议配 32GB 以上主机内存、50–100GB 可用磁盘；具体取决于模型缓存和输出保留策略。当前 Mac 可承担数据、文档和轻量 CPU 分析，未完成 NVIDIA 实测。

### 8.2 可复算的推理预算

以 10,000 道有效题、每题 4 个样本、每次输入 2,000 token／输出 256 token 为规划例：共 **8,000 万输入 token、1,024 万输出 token**。假设实际 prefill 500–2,000 token/s、decode 20–60 token/s，则串行纯推理约 59–187 小时，另加 I/O、失败重试和验证器成本。这只是不同吞吐情景的计算，不是任何显卡实测跑分；批处理与缓存会改变耗时。

用 100 道真实题测吞吐后，按公式更新：

`小时 ≈ (总输入token / prefill速度 + 总输出token / decode速度) / 3600`。

建议为 3 个月方案预留 **150–400 GPU 小时** 的规划空间，6 个月扩展约 **300–800 小时**；包含重复种子、消融、额外生成与可能的短微调，必须用首周测量调整。若每周仅能拿到 5 小时 GPU，总预算就明显不匹配，需要缩小采样次数或借助 API，不能只看显存说够用。

### 8.3 API 预算不依赖当前报价

若 2,000 条教师标注平均输入 3,000 token、输出 800 token，一轮约 600 万输入、160 万输出 token；加 20% 重试约 720 万／192 万。费用为 `7.2 × 每百万输入单价 + 1.92 × 每百万输出单价`，币种依所选服务报价。缓存命中／未命中价格不同，按实际账单拆分。API key 和账户预算尚未提供，因此本轮没有发起付费请求。

三个月路线优先把 API 用于有限训练难例和第二生成器的测试诊断，不用在全量多轮人工式标注上。原始回应缓存后，规则与指标分析不再重复调用。

## 9. 10–14 天开题预实验

| 时间 | 工作 | 明确产物／决策 |
|---|---|---|
| 第 1–2 天 | 读本轮近邻对照，固定任务；复查数据与坐标转换 | 输入 schema、不可读取的 gold 字段清单、版本化 split |
| 第 3–4 天 | 100 道实际 GPU 推理；若需要则 100 步 QLoRA | 峰值显存、吞吐、上下文长度分布；判定 24GB 与时间预算 |
| 第 5–6 天 | 在 G/V 预先抽定的 200–400 题跑固定候选；B0–B4 | 错误率、风险覆盖、执行成功率；不能以 gold 上限当模型成绩 |
| 第 7–9 天 | 候选绑定、top-1／独立／联合小样本比较 | Recall@k、数据对齐失败率、结构信号增益趋势 |
| 第 10–11 天 | 同特征分类器、单位／时期诊断；检查难例 | 判断收益来自新结构还是简单规则 |
| 第 12–14 天 | 汇总导师评审材料，决定继续／收窄／转题 | 一页问题、近邻差异表、一张实测曲线、资源表、后续计划 |

预实验不得用官方 T 反复迭代。首先看是否有稳定方向，不要求 200 题就证明统计显著。第 4 周仍无结构增益时停止扩充该机制；保留复现实验结果，转向经过重新检索的相邻问题。
